# 決定性と版

この描画器の値の約束と、それを守るための書き方の規則。Kura の `docs/editing.md` §8（決定性と版）を下敷きにし、
この描画器に合わせて足したものがある。規則の多くは `clippy.toml` と `tests/rules.rs`（src の走査）で強制する（§9）。

---

## 1. 約束

### 1.1 同じ入力の組なら同じ出力（D1・D2。ADR-33）

| 入力の組 | 中身 |
|---|---|
| SVG | バイト列 |
| フォント | 呼び手が渡したフォントの集まり（各フォントのバイト列・呼び手の鍵・並びの順） |
| 読みの設定 | 値に効く項目（言語の並び・既定の書体・総称の書体の割り当て・代わりの書体の並び・既定の文字の大きさ。architecture.md §3） |
| 描きの設定 | 倍率・描く範囲 |
| 画像のデコーダ | 呼び手が渡したデコーダの識別子（渡したときだけ。ADR-16） |
| 版 | 描画器の識別子（`sumie-render/<N>`。§8） |

約束は 2 つに分ける。

- **D1（値）**：入力の組が同じ（版が同じ）なら、対象のどのターゲットでも、次がビット単位で同じ。ライブラリの別の
  コミットでも、版が同じなら同じ
  - 画素（RGBA8、乗算済み）と大きさ
  - 報告のうち版に入る部分（使ったフォントの鍵と書体の番号・見つからなかった文字・使った画像のデコーダの識別子。§8.1）
- **D2（勘定）**：入力の組と上限が同じで、ライブラリのソース（git の rev）が同じなら、対象のどのターゲットでも、次が同じ
  - 見積もり（手間・確保の量）と、上限で断るかどうか（どの上限で断るか）
  - 報告の残り（読まなかった参照・警告。並びの順も含む）

見積もりと「断るかどうか」を約束に入れるのは、Kura がそれで予算を確保し、受け付けるかを決めるからである。時間で断らず、
手間の単位で断るので、同じ入力の組・上限・rev なら、どの環境でも同じ所で断る。見積もりの式・係数・警告は版を上げずに
直してよい（§8.2）ので、D2 は版ごとでなく rev ごとの約束にする（Kura は rev を固定して取り込む。ADR-18）。

### 1.2 値に効かないもの

次のものは D1 の値を変えない。変えたら不具合である。

- 上限（`Limits`）：上限は「断る」か「同じ値を返す」かのどちらかだけを決める。途中までの値を返さない。値に効く上限
  （字形ごとの上限・組版の上限。architecture.md §7.1）は `Limits` に入れず、版に入る定数にする
- 中止の印：「`Cancelled` を返す」か「同じ値を返す」かのどちらか。中止は時刻に依るので、どちらになるかは約束しない
- 確保の失敗：`try_reserve_exact` が失敗したときの `Limit` は、中止と同じく環境に依る（どちらになるかは約束しない）。
  返すなら「断る」で、違う値は返さない
- 範囲の描画の切り方：範囲を描いた画素は、全体を描いて同じ範囲を切り出したものとビット単位で同じ（ADR-13。§6）
- 呼び手のスレッドの数・どのスレッドで呼ぶか・同じ木を同時に何本描くか
- ビルドの設定：debug と release、`opt-level`、`target-cpu`・`target-feature`、LTO
- Rust のツールチェーンの版：変わりうる std の口を禁じて（§2.3・§4）、版に依らない書き方をする。ただし確かめるのは
  `rust-toolchain.toml` で固定した版だけ

### 1.3 対象のターゲット

| ターゲット | 確かめ方 |
|---|---|
| `aarch64-apple-darwin` | 手元（Apple M4 Max）と CI |
| `x86_64-unknown-linux-gnu` | CI（x86_64 の確かめの主） |
| `aarch64-unknown-linux-gnu` | CI |
| `x86_64-apple-darwin` | 手元で Rosetta 2 を通して（約束の外。x86_64 の命令で同じ値かを安く確かめられる。Apple は macOS 27 のあとに Rosetta 2 を絞ると告げているので、長くは頼らない） |

どれも 64 ビットで、浮動小数は IEEE 754 の binary32・binary64（x86_64 は SSE2。x87 は使われない）。CI は GitHub Actions で
3 つのターゲットを回す（ADR-22）。

Kura の R1 は aarch64-apple-darwin での一致を約束し、浮動小数の操作はターゲットごとのゴールデンを持つ（Kura の
`docs/editing.md` §8.1）。この描画器の約束はそれより強く、全ターゲットで同じ値にする。そうすれば Kura は、SVG の
デコーダのゴールデンを CI の ubuntu でも照らせる。

### 1.4 呼び手への前提

- 呼び手のスレッドの浮動小数の状態（丸めの向き・非正規化数を 0 にする FTZ・DAZ）は既定のまま呼ぶ。ライブラリは
  制御レジスタを触らない（`unsafe` を使わないので触れない）が、呼び手のほかの部品が変えていれば値が変わる
- Kura は乗算済みの出力をストレートに戻して値にしている。戻す式は Kura の側で凍結する（ライブラリの版の外）

## 2. 浮動小数

### 2.1 使ってよい演算

IEEE 754 で結果が一意に決まるものだけを使う。

- `+`・`-`・`*`・`/`・`sqrt`（正しく丸めると決まっている）・単項の `-`
- `abs`・`copysign`・`signum`・`floor`・`ceil`・`trunc`・`round`・`round_ties_even`・`fract`・`%`・`rem_euclid`・
  `div_euclid`・`recip`
- 比較（`<`・`==` など）と `total_cmp`
- 値の述語：`is_nan`・`is_finite`・`is_infinite`・`is_sign_positive`・`is_sign_negative`（ビットだけで決まる。ADR-56 (4)）
- `as` による変換（浮動小数から整数は飽和で、NaN は 0）・`f32` と `f64` の間の変換・`to_bits`・`from_bits`
- `str::parse::<f64>()`・`<f32>`（正しく丸めるので答えが一意。外から来た数の字句は自前で切り出し、ASCII の部分だけを渡す）

x86_64 の基準の命令（SSE4.1 がない）では、`floor`・`ceil`・`trunc`・`round`・浮動小数の `%` が libm の関数の呼び出しに
なることがある。どれも結果が正確に 1 つに決まる関数なので、どの libm でも値は変わらない（超越関数と違う）。

### 2.2 超越関数

sin・cos・tan・asin・acos・atan・atan2・exp・exp2・ln・log2・log10・pow・cbrt・hypot・sinh などは、
`crate::math` の関数だけで求める。`math` の中身は `libm = "=0.2.16"`（`default-features = false`。`arch` の
feature は CPU の命令の経路を選ぶので外す）の薄い包みで、std の `f32`・`f64` の超越関数（OS の libm を呼ぶ）は
clippy の `disallowed-methods` で禁じる。

### 2.3 禁じる演算（std にあるが使わない）

| 演算 | 理由 | 代わり |
|---|---|---|
| `mul_add` | 丸めが 1 回なので `a * b + c` と値が違い、基準の x86_64 では OS の libm の `fma` を呼ぶ（Kura の §8.2 は IEEE で一意として許しているが、この描画器は依頼の規則で使わない） | `a * b + c` と書く |
| `powi` | LLVM の組み込みで、展開のしかたが版・ターゲットで変わりうる | `math::powi`（掛け算の順を決めたもの） |
| 浮動小数の `max`・`min`・`maximum`・`minimum` | ±0 と NaN の扱いが定まらない・変わってきた | `math::max`・`math::min` |
| 浮動小数の `clamp` | NaN と上下の逆で panic する | `math::clamp` |
| `to_degrees`・`to_radians` | 掛ける定数が std の版で変わった過去がある | `math` の定数を掛ける |
| `midpoint`・`hypot` | 実装が std の版に依る・OS の libm を呼ぶ | 自前の式・`math::hypot` |
| `algebraic_add`・`algebraic_mul` など（1.99.0 で stable。禁じる口の一覧に入れた。ADR-49） | LLVM に並べ替え・縮めを許す | 素の演算子 |

整数の `Ord::max`・`min` は値が一意に決まるので使ってよい。`Ord::clamp` は上下の逆で panic するので禁じる
（`crates/sumie/clippy.toml`）。`x.max(lo).min(hi)` と書く。

`math::max`・`min` の規則：Kura の `math::max`・`min` と同じく、IEEE 754-2019 の maximumNumber・minimumNumber にする
（片方が NaN なら、もう片方を返す。-0 < +0 とみなし、`max(-0.0, +0.0)` は `+0.0`、`min(-0.0, +0.0)` は `-0.0`）。NaN は
値に入れないので、NaN が来るのは不具合。

### 2.4 演算の順

- 式は書いた順で計算する。足し算・掛け算を並べ替えない（結合の法則は浮動小数では成り立たない）
- 和は決めた順（添字の昇順・文書の順）で足す。木の形の和・分けた部分和を作らない
- `a * b + c` は FMA に縮まない（Rust は LLVM に縮めてよいと伝えない）。`target-cpu=native` でも同じ値になることを
  ゴールデンで確かめる
- LLVM の自動のベクトル化は浮動小数の結合を並べ替えないので、値を変えない（明示の SIMD は §7）

### 2.5 NaN・無限・±0・非正規化数

- NaN と ±∞ を値に入れない。外から来た数は解析の段で有限かを確かめ、有限でなければ壊れた値として扱う（その属性を無視して
  警告。FR-ST-15）。計算で NaN・∞ になりうる所（÷0・負の sqrt・大きな数の積）は手前で範囲を確かめる。変形のあとの点が
  有限でない節は描かない（architecture.md §6.1）
- NaN のビットの形（符号・中身）は CPU で違う（x86_64 と aarch64 で既定の NaN の符号が違う）。NaN を整数にしない・
  ダイジェストや比較の鍵に入れない
- ±0 は出力に効く所で区別しない（値で比べる。`to_bits` で比べない）
- 非正規化数はどのターゲットでもそのまま扱われる（段階的アンダーフロー）。§1.4 の前提のもとで値は変わらない

### 2.6 型の使い分けと大きさ

- 幾何・変形・色の中間の計算は `f64`、ラスタライズの被覆と画素の合成は整数（固定小数）を基本にする（architecture.md §6）。
  `f32` を使う所は、その理由と、`f64` に比べて値が変わることを承知している旨を注釈に書く。どちらの型でも、この節の規則は同じ
- 見積もり（D2）に入る大きさは、ツールチェーンで変わらないように決める：`mem` の入れ物（`MVec`・`Frozen`）に入れる型は
  すべて `#[repr(C)]` か基本の型にし、`size_of` を `cost` の定数と試験で照らす（`repr(Rust)` の型の大きさは Rust の版で
  変わりうる）。数える量は頼んだ容量で、`capacity()` は使わない（architecture.md §5.1）

## 3. 整数

- あふれうる所は `checked_*`・`saturating_*`・`wrapping_*` のどれかを明示する。素の `+`・`*` は、debug では panic し、
  release では折り返すので、ビルドで振る舞いが分かれる。あふれないと示せる所（範囲を手前で確かめた所）だけ素の演算を
  使い、その根拠を注釈に書く。clippy の `arithmetic_side_effects` で見張る（CLAUDE.md）
- 演算子でない口も同じ：整数の `pow`（`checked_pow` を使う）・`abs`（最小の値であふれる。`unsigned_abs`・`checked_abs`）・
  `Iterator::sum`・`product`（debug であふれると panic。`checked_add` で畳む）は禁じる
- ずらし（`<<`・`>>`・`<<=`・`>>=`）は、ずらし量が桁の数以上だと debug でだけ panic し、release では下位のビットで
  折り返す。`arithmetic_side_effects` はずらし量が変数のずらしを拾わない（1.99.0 で確かめた）ので、`tests/rules.rs` が
  「ずらし量が数の字句か定数でないずらし」を拾う。変数のずらしは `checked_shl`・`checked_shr` で書く
- ÷0 で panic しないよう、除数は手前で確かめるか `checked_div` を使う
- 負の数の `/` は 0 の向きに切る。固定小数の丸めは、使う所ごとに `div_euclid`・右シフト・自前の丸めの関数のどれかに
  決めて注釈に書く
- 数・大きさ・手間は `u64` で持つ。添字は `usize` で、`u64` からは `usize::try_from` で移す
- release の profile の `overflow-checks` は既定（切）のまま。ファズは `cargo fuzz` の既定（debug-assertions と
  overflow-checks が入る）で回し、示しそこなったあふれを panic として見つける

## 4. 順序・入れ物・文字の判定

### 4.1 順序

- `HashMap`・`HashSet`・`RandomState`・`DefaultHasher` を使わない（反復の順がプロセスごとに変わる・ハッシュの値が
  Rust の版で変わりうる）
- 順序の要る表は、`mem` の並べた入れ物（`SortedVec`・`SortedMap`）を使う。探すのは自前の `lower_bound`（等しいものが
  並ぶときは最初の位置を返すと決めたもの）
- 並べ替えは `mem::stable_sort`（自前の安定な併合の並べ替え）だけ。比べる関数は全順序にする（浮動小数は `total_cmp` か
  整数の鍵）。全順序でない比べ方（`partial_cmp(..).unwrap_or(Equal)` など）をしない（`tests/rules.rs` が `partial_cmp` の
  呼び出しを拾う）
- `sort_unstable*`・`select_nth_unstable*`・`binary_search*` を使わない
- ポインタの値・確保の順で順序や鍵を決めない（`tests/rules.rs` が `as_ptr`・`addr`・`*const`・`*mut` を拾う）
- 文書の中の処理は文書の順（木の行きがけの順）で行う。ID の重複・規則の重なりなどは、文書の順で決める規則を requirements.md に書く

### 4.2 std の入れ物と並べ替えを使わない理由（ADR-31）

`BTreeMap`・`BTreeSet`・`BinaryHeap`・`VecDeque`・`slice::sort`・`sort_by`・`sort_by_key`・`sort_by_cached_key` は、std の
中で確保し（失敗すれば abort する）、`Budget` で数えられない。順序は決まっていても、安全の規則（確保は `mem` の口だけ）を
守れないので、ライブラリでは使わない（`disallowed-types`・`disallowed-methods`）。

### 4.3 文字の判定

- std の Unicode の表に依る関数を使わない：`char::is_whitespace`・`is_alphabetic`・`is_numeric`・`is_alphanumeric`・
  `is_lowercase`・`is_uppercase`・`is_control`・`to_lowercase`・`to_uppercase`、`str::trim`・`trim_start`・`trim_end`・
  `split_whitespace`・`to_lowercase`・`to_uppercase`。std の表は Rust の版で上がり、しかも `trim` は U+00A0・U+3000 も
  削るので、XML・CSS の空白の扱いとしても誤り
- 使ってよいもの：`is_ascii_*`・`to_ascii_*`・`eq_ignore_ascii_case`・`trim_ascii*`。XML の空白は #x20・#x9・#xD・#xA、
  CSS の空白は CSS Syntax の定義で、自前の関数にする
- Unicode の属性は、版を固定して生成した自前の表（architecture.md §7.2）だけから引く

## 5. 乱数・時刻・環境

- 乱数を使わない。feTurbulence の擬似乱数は仕様が決めた整数の漸化式で、乱数ではない（仕様の式どおりに書く）。
  ほかで要るときは種つきの ChaCha8 を自前で書き、種と流れの決め方を decisions.md に書く
- 時刻（`Instant`・`SystemTime`）・環境変数・コマンドの引数・ロケール・ファイル・ネットワーク・スレッドの番号を読まない
- 手間の数え方と中止の確かめの間隔は定数で、時刻に結び付けない（中止の印を読むだけ）

## 6. 並列と範囲の描画

- ライブラリはスレッドを作らない（`std::thread` を使わない。依存に rayon を入れない）
- 描く木（`Tree`）とフォントの集まり（`FontSet`）は作ったあと変わらず、`Send + Sync`。描くのは `&Tree` で、呼び手は同じ木を
  複数のスレッドで同時に描ける
- 範囲の描画（ADR-13）のため、**画素の値は、その画素の位置・木・設定だけで決まる**ように書く。範囲の左上・大きさ・
  描く順に依らない
  - 平坦化の点・線の外形・破線の位相は、切る矩形（キャンバス・範囲）に依らずに決める。切り取りは矩形の中の値を変えない
    形で行う（architecture.md §6.1。ADR-30）
  - ラスタライズの被覆は整数で積むので、範囲の外から始まる走査線の積み上げも同じ値になる
  - 走る和（ぼかしの箱の和など、足して引く和）は整数で持つ。浮動小数の走る和は、始める位置で丸めの誤差が変わる
  - フィルタのように近くの画素に依るものは、中で計算する範囲を reach の分だけ広げて求め、広げられないものは領域全体を求める
  - pattern のタイル・フィルタの計算面・mask の層は、範囲に依らない格子と大きさで作る（範囲で切るのは最後の写しだけ）
  - 一時の画像の原点は、範囲でなく、木の座標（キャンバスの画素の格子）に揃える
- 範囲の描画と、全体を描いて切り出したものの一致を、ランダムな矩形で確かめる（§9）

---

## 7. SIMD・ターゲットによる枝

- 明示の SIMD を書かない。`std::arch`・`core::arch` は、ターゲットで有効な機能の組み込みなら `unsafe` なしでも呼べる
  （Rust 1.87 から）が、ターゲットごとに書き分けることになるので使わない（`tests/rules.rs` で禁じる）。`std::simd` は
  stable にない
- `#[cfg(target_arch)]`・`#[cfg(target_os)]`・`#[cfg(target_feature)]`・`is_x86_feature_detected!` でライブラリの
  処理を分けない（道具とテストの中は、照合の相手を選ぶためだけに許す）
- 速さは、自動のベクトル化が効く形（整数の配列の素直なループ）で稼ぐ

## 8. 版

### 8.1 識別子

- 描画器の識別子は `sumie-render/<N>`。公開の定数 `sumie::RENDERER` に置く。開発中は `N = 0`、M7 で `1` に凍結し、
  そのあとは値を変えるたびに 1 ずつ上げる
- 版に入るもの（D1）：画素・大きさ・報告の「使ったフォントの鍵と書体の番号」「見つからなかった文字」「使った画像のデコーダの
  識別子」。これらのどれかが、ある入力で変わる変更は `N` を上げる
- 版に入る定数：字形ごとの上限・組版の上限（当てはめの回数・歩数・入れ子の深さ）・平坦化の許容の誤差・総称の書体の既定の割り当て・Unicode の表
- 版に入らないもの（D2）：警告の文言・種類（足してよい）、見積もりの式と係数（実際以上を保つ限り直してよい）、上限の既定値、
  速さ
- Unicode の版は、表を作る道具と元のデータのダイジェストとともに記録し、上げるときは `N` を上げる

### 8.2 版を上げる変更・上げない変更

| 変更 | 版 |
|---|---|
| ある入力の画素・大きさが 1 ビットでも変わる（不具合の修正を含む） | 上げる |
| フォントの選び方・代わりのフォントの探し方が変わる | 上げる |
| 字形ごとの上限・組版の上限が変わる | 上げる |
| `FontSet::new` が書体を受ける・飛ばす判定が変わる（`faces()` の並びと代わりのフォントの選び方が変わる） | 上げる |
| 断っていた入力を描けるようにする（前は値がなかった） | 上げない（decisions.md に書く） |
| 描けていた入力を断るようにする | 上げない。ただし Kura が描けなくなるので、ユーザーの承認を得る |
| 値の変わらない速さの改善・見積もりの改善・警告の追加 | 上げない（D2 が rev ごとに変わる） |

旧版の実装はライブラリに残さない。旧版の値が要るときは、Kura が rev の違う 2 つを別名の依存で持つ（ADR-18）。

版を上げるときは、新しい版のファイル（`render-v<N+1>.jsonl`）に全部の例を描き直して足す。古い版のファイルは記録として
残し、照らすのは今の版のファイルだけ（古い版の値は、その版の rev で照らせる）。

### 8.3 開発中の版

M7 で `sumie-render/1` を凍結するまでの値は版 0（`sumie-render/0`）とする。版 0 のゴールデンは仮の値として作り直して
よい（作り直すときはコミットを分け、差の一覧を付ける）。ターゲットの間の一致は版 0 でも毎回確かめる。凍結したあとは
§10 のとおり追記だけ（ADR-20）。

## 9. 確かめ方

| 何を | どうやって |
|---|---|
| 禁じた口（超越関数・`HashMap`・`BTreeMap`・std の並べ替え・std の Unicode の判定・`sort_unstable` など） | `clippy.toml` の `disallowed-methods`・`disallowed-types`・`disallowed-macros` |
| `cfg(target_*)`・`std::arch`・`mul_add`・確保の口の外での確保・`unsafe` | `tests/rules.rs`（src の走査）と `#![forbid(unsafe_code)]` |
| std の中の確保の漏れ | 確保を数える確保器の試験（architecture.md §5.1） |
| ターゲットをまたいで同じ値 | ゴールデン（§10）を全ターゲットで照らす |
| ビルドの設定で値が変わらない | ゴールデンを debug・release・`target-cpu=native` で照らす |
| 範囲の描画が全体の切り出しと同じ | 種つきのランダムな矩形（端・1 画素・空・全体・境目をまたぐ曲線と破線を含む）で比べる性質のテスト |
| 上限・中止で値が変わらない | 上限を変えて「断る」か「同じダイジェスト」か、中止を手間の途中で立てて「`Cancelled`」か「同じダイジェスト」かを確かめる |
| 見積もりが実際以上 | 照合の集まりと敵対的な入力のすべてで、数えた手間・確保の量が見積もり以下（requirements.md） |
| D2 がターゲットをまたいで同じ | 見積もりと警告の並びのダイジェストを、ゴールデンとは別のファイル（`goldens/estimate.jsonl`。rev ごとに作り直してよい）で全ターゲットで照らす |

## 10. ゴールデン

- 1 行 1 例の JSON Lines。行は「例の名前・入力のダイジェスト・フォントの鍵の並び・画像のデコーダの識別子・設定・大きさ・
  画素のダイジェスト・版に入る報告のダイジェスト」
- 入力そのものは `tests/svg/`（自作）か、取り込んだ照合の集まり（出どころの一覧つき。ADR-21）に置き、行はダイジェストで指す
- フォントは `tests/fonts/` のものだけを使う（macOS のシステムのフォントは Linux の CI にない。システムのフォントで描く照合は
  ゴールデンにせず、手元の照合の一覧にする）
- ファイルは版ごと（`goldens/render-v<N>.jsonl`）。凍結した版のファイルは**追記だけ**で、既存の行を書き換えない・消さない。
  今の版より古い版のファイルは追記もしない（記録として変えない。ADR-51 (5)）
  例の中身（名前・入力・設定）を変えたいときは、新しい名前の例を足す。`scripts/check-goldens-append-only.sh` が CI と
  手元の全チェックで見張る。版 0 の `render-v0.jsonl` は今の版が 0 の間だけ見張りから外し（作り直してよい。ADR-20）、今の
  版が 1 以上になったら古い版として凍結する（ADR-56 (3)）。`estimate.jsonl` は見張らない（D2 は rev ごと）
- 同じファイルを全ターゲットで照らす（ターゲットごとのゴールデンは持たない。持つ必要が出たら、それは決定性の不具合）
- ダイジェストは BLAKE3（dev 依存）。画素は幅・高さ・行を詰めた RGBA8 を続けたバイト列から取る
